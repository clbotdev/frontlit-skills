# FrontLit skills

Agent skills for FrontLit.

| Skill | What it does |
| --- | --- |
| [`frontlit-docs`](plugins/frontlit-docs/skills/frontlit-docs/SKILL.md) | Write FrontLit docs, or port an existing docs site (Fumadocs, Docusaurus, Mintlify, Nextra, GitBook, VitePress) to FrontLit and open a pull request |
| [`frontlit-pages`](plugins/frontlit-pages/skills/frontlit-pages/SKILL.md) | Write FrontLit landing pages as JSON (`frontlit/pages/*.json`, `frontlit/site.json`), validate them and open a pull request |
| [`frontlit-builder`](plugins/frontlit-builder/skills/frontlit-builder/SKILL.md) | Build pages in FrontLit's visual page builder: themes from a design system, high-end section design, Embed snippets that work in FrontLit's shadow root (with a headless-Chrome test harness), comparison pages |

## Install

Any agent that supports skills (Claude Code, Codex, OpenCode, Gemini CLI, Cursor, Copilot…):

```
npx skills add codelitdev/frontlit-skills --skill frontlit-docs
npx skills add codelitdev/frontlit-skills --skill frontlit-pages
npx skills add codelitdev/frontlit-skills --skill frontlit-builder
```

Claude Code plugin:

```
/plugin marketplace add codelitdev/frontlit-skills
/plugin install frontlit-docs@frontlit
/plugin install frontlit-pages@frontlit
/plugin install frontlit-builder@frontlit
```

## Use

Connect your repository in FrontLit (Settings → Integrations → GitHub) first. Then, in your repository:

```
Use the frontlit-docs skill to port my existing docs to FrontLit and open a pull request.
Use the frontlit-pages skill to add a pricing page and link it from the header.
Use the frontlit-builder skill to build a comparison page in the FrontLit builder, as a draft.
```

frontlit-docs and frontlit-pages work on the repository's FrontLit site folder (`frontlit/` by default): docs in `docs/`, pages in `pages/`, header, footer and theme in `site.json`.

## Keeping in sync

- **frontlit-docs:** `references/format.md` and `scripts/check.mjs` mirror FrontLit's Markdown importer and validator. Update them whenever those rules change in the FrontLit repository.
- **frontlit-pages:** `scripts/schema/page.v1.json` and `site.v1.json` are copies of `packages/page-builder/schema/` in the FrontLit repository (generated by `bun run schema:generate` there). Copy them again whenever block settings change, then, from `plugins/frontlit-pages/skills/frontlit-pages/examples`, run `node ../scripts/check.mjs frontlit/pages --fix` (the examples must stay valid and canonical) and update `references/blocks.md`. The import rules in `scripts/check.mjs` and `references/format.md` (file names, reserved routes, content feeds, link and image checks) mirror `apps/api/src/pages/git-import.ts`.
- **Shared design references:** `references/embeds.md`, `design.md`, `comparison-pages.md`, `theme-from-design-system.md` and `scripts/test-embed.mjs`, `scripts/oklch-to-hex.mjs` exist in both `frontlit-builder` and `frontlit-pages` (each skill installs on its own), and must stay identical: edit them in `frontlit-builder`, copy them to `frontlit-pages`, and check with `for f in references/{embeds,design,comparison-pages,theme-from-design-system}.md scripts/{test-embed,oklch-to-hex}.mjs; do diff -q plugins/frontlit-builder/skills/frontlit-builder/$f plugins/frontlit-pages/skills/frontlit-pages/$f; done`. `embeds.md` and `test-embed.mjs` mirror FrontLit's `packages/page-builder/src/components/inline-embed.tsx` (`prepareEmbed`, `runScripts`); update them when that file changes.
